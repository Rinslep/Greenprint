## Step 5 — Broken Blueprint Detector (`pipeline/broken_detector.py`)

### What it does

Scans a validated blueprint and attaches a list of flag dicts describing potential problems.
Flags do **not** prevent storage — they are informational/warning metadata.

### Implementation

```python
def detect(blueprint: BlueprintWrapper) -> list[dict]:
    """Returns list of {flag, severity, detail} dicts."""
```

Each detector is a private function returning zero or one flag dict:

| Function | Flag | Severity | Logic |
|---|---|---|---|
| `_check_no_power` | `NO_POWER` | HIGH | No entity whose name is in the set of pole names from `reference_loader` |
| `_check_power_gap` | `POWER_GAP` | MEDIUM | Build pole coverage set (position ± supply_area/2 tiles). For each machine, check if any tile in its footprint overlaps. Use `reference_loader.get_entity` for sizes and pole supply areas |
| `_check_floating_inserter` | `FLOATING_INSERTER` | LOW | For each inserter, check pickup and drop positions (based on direction + reach) for an adjacent entity within 1–2 tiles |
| `_check_belt_dead_end` | `BELT_DEAD_END` | MEDIUM | For each belt, check its output tile in flow direction — flag if no belt/machine/chest/loader/underground exit at that position |
| `_check_unsupplied_recipe` | `UNSUPPLIED_RECIPE` | HIGH | For each machine with a recipe, check if every recipe input has at least one inserter pointing into the machine. This is a simpler proxy check — full lane tracing comes in Step 10 |
| `_check_conditional_behaviour` | `CONDITIONAL_BEHAVIOUR` | INFO | Any entity has non-None `control_behavior` with circuit network connections |

The EARLY_VERSION and INFERRED_RECIPE flags are set by other modules — not duplicated here.

### Spatial lookup

Build a position index at the start of `detect()`: a dict mapping `(round(x), round(y))` to
a list of entities at that position. This avoids O(n²) entity-pair checks.

## Step 6 — Recipe Inference & Review Queue

### 6a. Recipe Inference (`pipeline/recipe_inference.py`)

For each machine entity in the blueprint where `recipe` is None:

1. Find all inserters whose drop position is within reach of the machine (input inserters)
2. Collect item hints:
   - From inserter `filters` field (explicit item filter list)
   - From inserter `control_behavior` (circuit-conditioned filters)
3. Cross-reference with `reference_loader.load_recipes()`:
   - Filter to recipes whose `valid_machines` includes this machine's entity name
   - Keep only recipes whose input items are a subset of the observed item hints
4. Resolution:
   - **1 match** → set `entity.recipe = match`, append `INFERRED_RECIPE` flag
   - **Multiple matches** → call `review_queue.add()` with all candidates
   - **0 matches** → call `review_queue.add()` with "no candidate found"

## Step 7 — Crafting Graph (`analysis/crafting_graph.py`)

### Implementation

```python
def build_crafting_graph(blueprint: BlueprintWrapper) -> nx.DiGraph:
```

1. Collect all machines with a recipe (explicit or inferred). Skip machines with no recipe.
2. For each machine's recipe, look up inputs/outputs from `reference_loader.get_recipe()`.
3. Create item nodes. For each recipe, add edges from each input item to each output item.
4. If multiple machines run the same recipe, sum `machine_count` on the edge.
5. Compute derived properties as graph attributes:
   - `final_products`: items that are produced (have incoming recipe edges) but not consumed
     (no outgoing recipe edges leading to another recipe that uses them)
   - `raw_inputs`: consumed but not produced
   - `intermediates`: both produced and consumed
   - `is_self_contained`: no intermediate appears in raw_inputs
   - `has_cycle`: try `nx.find_cycle(G)` — set True if found, False otherwise

## Step 8 — Ratio Analyser (`analysis/ratio_analyser.py`)

### Implementation

```python
def analyse_ratios(blueprint: BlueprintWrapper, crafting_graph: nx.DiGraph) -> dict:
```

For each machine, compute output rate as `fractions.Fraction`:

```
rate = Fraction(output_count, 1) / Fraction(crafting_time).limit_denominator(10000)
       * Fraction(crafting_speed).limit_denominator(10000)
       * module_speed_multiplier
       * (1 + productivity_bonus)
```

Module handling:
- Read each entity's `items` dict (keys are module names, values are counts)
- Look up module bonuses from `reference_loader.load_entities()` (items with `module` key
  in `data-1-1.json` — these need to be included in entities.json or loaded separately)
- For beacons: find beacon entities, compute which machines fall within `beacon_range` tiles,
  apply `effectivity * module_bonus` to those machines

Output per recipe pair:
```python
{
    (supplier_recipe, consumer_recipe): {
        "ideal_ratio": Fraction,
        "actual_ratio": Fraction,
        "efficiency": float,
    }
}
```

Bottleneck: the pair with the lowest efficiency.

### Module data gap

The current `reference/entities.json` does not include modules (speed-module, productivity-module,
etc.) since they are items, not placeable entities. However, blueprints reference modules by name
in entity `items` dicts. **Action:** Add module data to the reference loader — either extend
`entities.json` or create a separate `reference/modules.json` from `data-1-1.json`.

All tests listed in the existing stub. Key verification:

## Step 10 — Lane Model (`analysis/motif/lane_model.py`)

**Note: Moved before Step 9 because throughput analysis depends on it.**

### Implementation

```python
def build_lane_model(blueprint: BlueprintWrapper) -> nx.DiGraph:
```

This is the most complex single module. Build a directed graph where:

**Node types:**
- `(x, y, "left")` and `(x, y, "right")` — belt lane nodes
- `("machine", entity_number)` — machine entity nodes
- `("chest", entity_number)` — chest/loader entity nodes

**Edge construction (in order):**

1. **Belt flow edges:** For each belt entity, compute the output tile based on direction.
   Add edges: `(x, y, side) → (x+dx, y+dy, side)` for both lanes. Direction → delta:
   - 0 (N): dy = -1
   - 2 (E): dx = +1
   - 4 (S): dy = +1
   - 6 (W): dx = -1

2. **Underground belt edges:** Match pairs by: same belt tier, one `type="input"` and one
   `type="output"`, same direction, within `underground_max_distance`. Add a single edge
   from entrance lanes to exit lanes.

3. **Splitter edges:** Identify splitter entities (2×1 footprint). Map input lanes (2) to
   output lanes (2). If `filter` set, encode filtered item type on the output edge. If
   `output_priority` or `input_priority` set, encode as edge attribute.

4. **Inserter edges:** For each inserter, compute pickup position and drop position based on
   direction and reach. Determine what entity (belt lane, machine, chest) is at each position.
   - Belt pickup/drop: connect to the nearest lane node `(x, y, side)`
   - Machine pickup/drop: connect to `("machine", entity_number)`
   - Machine-to-machine (no belt): direct edge `("machine", src) → ("machine", dst)` with
     inserter as edge attribute — **first-class case, not an afterthought**

**Helpers needed:**
- `_direction_to_delta(direction: int) -> tuple[int, int]`
- `_compute_inserter_positions(entity) -> tuple[Position, Position]` (pickup, drop)
- `_find_entity_at(position, entities_by_pos) -> entity | None`
- `_determine_lane_side(inserter_pos, belt_pos, belt_direction) -> str` ("left" or "right")

### Implementation

```python
def analyse_throughput(
    blueprint: BlueprintWrapper,
    crafting_graph: nx.DiGraph,
    lane_graph: nx.DiGraph,
) -> dict:
```

For each connection path in the lane graph (machine output → machine input):

1. **Machine output rate** — reuse rate calculation from ratio_analyser
2. **Inserter delivery rate** — `inserter_stack_size × inserter_swing_speed × count`
3. **Belt lane capacity** — for each lane node in the path, check `belt_speed` from reference
4. **Bottleneck** — minimum of the three layers

Output:
```python
{
    "actual_output_rate": {item_name: Fraction},
    "bottleneck_entity": entity_number,
    "bottleneck_type": "machine" | "inserter" | "belt_lane",
    "lane_saturation": {(x, y, side): float},
}
```

### 11b. Canonicaliser (`analysis/motif/canonicaliser.py`)

```python
def canonicalise(motif_subgraph: nx.DiGraph) -> tuple[str, list[dict]]:
```

The 8-transformation approach:
- 4 rotations × 2 mirror states
- Position rotation: `(x, y) → (-y, x)` for 90° CW
- Position mirror: `(x, y) → (-x, y)`
- Direction rotation: `(d + 2) % 8`
- Direction mirror: swap E↔W, i.e. `{0:0, 2:6, 4:4, 6:2}`
- Serialize each transformation, pick lexicographic minimum, MD5 hash it
